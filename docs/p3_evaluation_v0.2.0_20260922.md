### 失败样本方向分析

结合原图检查，13张失败照片中有12张的目标铅封号都处于同一种竖排方向：必须将原图
顺时针旋转90度，目标号码才会变成正常的水平阅读方向。抽查的成功样本则主要是相反的
竖排方向。这与人工查看历史批量OCR结果时观察到的现象一致，说明当前OCR链路对两种
90度竖排方向的识别能力明显不对称。

其中两张已经出现局部识别：`F136644.jpeg`识别出`0488217`但漏掉前缀`23`，
`F136715.jpeg`识别出`542615`但漏掉前缀`V`；其余同方向失败样本大多没有在OCR文字中
保留足够信息，因此仅修改铅封号字符串提取规则无法恢复正确答案。

唯一明显例外是`F127125.jpg`：正确值`R0469076S`在图中已经接近水平方向，但OCR选择了
铅封侧面的另一串字符。该样本应单独归入小字、清晰度、检测区域或候选选择问题，不能
依靠整图顺时针旋转解决。

当前服务明确关闭了文档方向分类和文本行方向分类。PaddleOCR内置文本行方向模型只处理
0度和180度；即使将它打开，也不能直接覆盖本批次的90度与270度差异。下一项实验应在
固定44张铅封基准集上分别执行原图、顺时针90度和逆时针90度OCR，统计每个方向的救回
数量及对原有31张成功样本的影响，再决定生产模式采用固定双方向识别还是低置信度回退。

## 结论与下一步

P3 GPU端到端批量基线和13张铅封失败样本的首轮归因已经完成。下一步先做铅封号三方向
对照实验，验证旋转策略并记录救回和退化样本；随后再针对唯一的非方向失败样本和箱号
校验位做局部裁剪、放大或二次OCR实验。优化前后必须继续使用同一份133张固定基准集
比较，不能只观察个别成功照片。

## 三方向实验执行方法

实验由`scripts/evaluate_seal_orientations.py`执行。脚本不修改原始照片、数据库和服务，
每张照片的旋转版本只存在于临时目录。P3使用现有服务镜像运行测试客户端，并通过宿主机
网络访问仍在运行的`127.0.0.1:8800`服务：

```bash
cd /home/lucas/rpa/das_photo_ai
sudo docker run --rm \
  --network host \
  --user "$(id -u):$(id -g)" \
  --entrypoint python \
  -v "$PWD":/workspace:ro \
  -v /home/lucas/ai-lab:/home/lucas/ai-lab \
  -w /workspace \
  das-photo-ai:0.2.0 \
  -m scripts.evaluate_seal_orientations \
  --report /home/lucas/ai-lab/ocr_eval_manifest_v1_20260922.json \
  --seal-root /home/lucas/ai-lab/input/sealno_test \
  --api-base http://127.0.0.1:8800/api/v1 \
  --engine paddle_gpu \
  --output-dir /home/lucas/ai-lab/evaluation-runs/v0.2.0-seal-orientations
```

共执行132次请求。`summary.json`汇总三个方向各自的准确率、相对原图救回和退化的文件，
以及任一方向命中后的组合准确率；`comparison.csv`用于逐张核对。中断后给相同命令增加
`--resume`可继续，增加`--resume --retry-failures`可重试接口失败项。

## 三方向实验结果

- 实验时间：2026-09-22
- 总请求数：132
- API成功：132
- API错误：0
- 总墙钟时间：44.581秒

| 输入方向 | 第一候选正确 | 候选包含正确答案 | 平均服务耗时 |
|---|---:|---:|---:|
| 原图 | 31 / 44（70.45%） | 31 / 44（70.45%） | 147.166毫秒 |
| 顺时针90度 | 13 / 44（29.55%） | 14 / 44（31.82%） | 173.417毫秒 |
| 逆时针90度 | 24 / 44（54.55%） | 29 / 44（65.91%） | 174.706毫秒 |

顺时针90度相对原图救回10张，验证了人工观察到的方向问题；逆时针90度另外救回
`F136644.jpeg`。以正确答案进行离线核对时，三个方向任一第一候选正确的照片共有42张，
覆盖率为95.45%。`F120131.jpeg`的顺时针结果中已经包含正确候选`230418426`，但它排在
第三位；把所有候选也计入后，正确答案覆盖43 / 44（97.73%）。

当前三个方向均未产生完整正确候选的只剩`F136715.jpeg`。原图和逆时针结果都是
`542615`，缺少前缀`V`，需要继续做局部裁剪、放大或图像增强实验。

95.45%是使用正确答案事后判断“哪个方向命中”的覆盖率，不是当前服务可直接达到的
自动选择准确率。将三个方向的第一候选直接按现有`extraction_score`或OCR置信度取最高，
只能正确选择36 / 44。下一步必须先离线开发多方向候选融合与排序规则，利用候选结构、
长度、字符组成、跨方向一致性、分组位置和OCR置信度自动选择，再使用固定基准集验证；
在融合策略验证前，不把三方向识别直接接入生产接口。
